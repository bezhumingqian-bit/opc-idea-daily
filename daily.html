01 OpRun——Agent 运营预算与毛利核算层 · Runable $21M 负毛利：AI 把运营交给 agent 跑，账却没人算得清
9 月中旬，Runable 官宣 $21M Series A（Susquehanna Venture Capital + Nexus Venture Partners 领投）：1.5M 用户、上线 3 周 ARR 破 $2M、估值约 $65M——但媒体拆解其成本结构后点破一个关键事实：负毛利。给 1.5M 用户跑复杂 agent 的推理成本跑赢了收入，创始人 Umesh Kumar 把论题浓缩成"output 与 outcome 的区别"：大多数 AI 工具停在生成内容/代码（output），Runable 要做的是"build, run, and grow a business"（outcome）。同日 HN 榜首不是模型、不是融资，是一篇开发者自省《I stopped drinking the AI Kool-Aid》：token 成本随上下文非线性涨、prompt 随上游模型更新悄悄腐烂、非确定性产出让回归测试近乎不可能。同向信号密集：MakersClaw 2.0（PH，"agent 运营公司的 OS"，自带 budget、连续跑 go-to-market）、Bolt Forge（开源模型 50X 用量降本）。核心洞察：AI 把"做出来"和"跑起来"的成本都打下来后，一人公司开始把"运营"也交给 agent——但负毛利说明"算不清账"才是下一个坑。
OPC 路径：做"OpRun"——Agent 运营预算与毛利核算层。定位：一人公司把获客/客服/内容/支付交给 agent 跑，最怕"agent 干得很勤，账却是负的"。缺的不是又一个 agent，是"让 agent 在预算内跑、每项自动化算得清毛利"的核算层。① 运营预算（核心产品。给每个 agent 自动化设预算上限，接近阈值自动降级/暂停/换便宜模型）。② 毛利核算（把每项自动化的推理成本、渠道成本、带来的收入串成一条毛利账，agent 每天巡检异常）。③ 停损护栏（负毛利任务自动熔断，回报不达标的自动化自动下线）。定价：Free——单自动化预算。Maker——¥29/月，3 项自动化 + 毛利核算。Pro——¥99/月，不限自动化 + 停损护栏 + 团队共享。冷启动：渠道 A——开源"OpRun Core"成本核算 CLI。渠道 B——数据帖"AI 把运营交给 agent 跑，负毛利没人算得清"。渠道 C——搭 Runable $21M 顺风车。Founding Member：Pro ¥49/月终身。

02 ToolBridge——Agent 工具调用协议适配与路由层 · Ruby UTCP：MCP 之外，工具调用协议在分化
9 月 19 日，Ruby UTCP 冲上 Product Hunt 当日榜，定位"MCP 的可扩展、安全替代方案"，实现 UTCP 1.1（Universal Tool Call Protocol）：12 种传输、streaming、auth、OpenAPI 自动发现、CodeMode 可编程多工具工作流。同日 GitHub 趋势上 tool-calling / computer-use 生态持续分化：trycua/cua（computer-use 2.0 开源驱动，+859 星当日）、affaan-m/ECC（面向多种编码 agent 的性能与流程优化 harness，26 万星）、addyosmani/agent-skills（生产级 agent 工程技能，9.7 万星）。核心洞察：MCP 成为事实标准之后，工具调用协议开始分化——一个人同时用 Claude Code / Codex / Cursor，每个都有自己的工具生态，工具"一次开发、处处可用"成了新的缺口。
OPC 路径：做"ToolBridge"——Agent 工具调用协议适配与路由层。定位：一人公司给不同 agent 接 MCP server / 工具时，要按 Claude Code / Codex / Cursor 各自的协议重复适配。缺的不是又一个协议，是"工具一次注册、跨 MCP / UTCP / ACP 处处可用"的适配路由层。① 协议适配（核心产品。工具一次声明，自动生成 MCP / UTCP / ACP 多协议适配，跨 agent 复用）。② 智能路由（按 agent 的协议、权限、延迟自动选择最优传输与工具实现）。③ 安全网关（统一的鉴权、审计、速率限制，工具调用可追溯）。定价：Free——单协议适配。Maker——¥29/月，3 个工具 + 智能路由。Pro——¥99/月，不限工具 + 安全网关 + 团队共享。冷启动：渠道 A——开源"ToolBridge Core"协议适配层。渠道 B——数据帖"MCP 之外，工具调用协议在分化"。渠道 C——搭 Ruby UTCP 顺风车。Founding Member：Pro ¥49/月终身。

03 ScreenSide——看屏 GUI 自动化层 · Sider Omni Sidebar + CUA-S1：你的 Mac 每个 App 都该有个 agent 侧边栏
9 月 18-19 日，Sider Omni Sidebar 冲上 Product Hunt 当日前列（371-374 票），定位"给每个 Mac App 一个 agent 侧边栏"：agent 直接看屏、直接在 App 上操作，复用你已有的 ChatGPT / Codex credits（GPT-6 Astra），不用复制粘贴或上传内容。同向信号密集：CUA-S1（HN，桌面 UI 自动化模型，"像快速反应的大脑直接控制桌面界面"）、trycua/cua（+859 星，computer-use 2.0 开源驱动，跨 OS fleet）、Cactus Needle（2-bit / 8-29MB 边缘自动化模型，跑在手机/穿戴/家居/微控制器上）。核心洞察：agent 从"终端里干活"走向"看屏操作任意 App"——一人公司那些跨 App 的重复 GUI 杂活（搬数据、录报销、导报表、跨系统对账）还靠人手，是下一块待自动化的地。
OPC 路径：做"ScreenSide"——看屏 GUI 自动化层。定位：一人公司的重复性 GUI 操作（把 A 平台数据搬到 B、录报销、导周报、跨 App 对账）仍靠人手点。缺的不是又一个模型，是"看屏 + 点界面 + 复用已有 credits"的 GUI agent 层。① 屏幕感知（核心产品。截屏理解任意 App 界面，无需 API / 插件）。② 动作执行（鼠标 / 键盘 / 表单自动操作，跨 App 搬运数据、录单、导出）。③ 复用已有 credits（跑在你已有的 ChatGPT / Codex / 本地模型上，不叠加新订阅）。定价：Free——单屏识别。Maker——¥29/月，3 个自动化脚本 + 动作执行。Pro——¥99/月，不限脚本 + 跨 App 编排 + 团队共享。冷启动：渠道 A——开源"ScreenSide Core"屏幕感知引擎。渠道 B——数据帖"你的 Mac 每个 App 都该有个 agent 侧边栏"。渠道 C——搭 Sider Omni Sidebar 顺风车。Founding Member：Pro ¥49/月终身。

本期钩子
9 月 21 日三条信号指向同一件事：当"做出来"和"跑起来"都不再是瓶颈，一人公司的下一道坎回到"把 agent 塞进真实业务之后，怎么算得清、接得通、干得了"。信号一：Runable $21M 负毛利 + HN《I stopped drinking the AI Kool-Aid》——"AI 把运营交给 agent 跑，负毛利没人算得清"，这就是 OpRun（运营毛利核算层）。信号二：Ruby UTCP——"MCP 之外，工具调用协议在分化"，这就是 ToolBridge（协议适配路由层）。信号三：Sider Omni Sidebar + CUA-S1——"你的 Mac 每个 App 都该有个 agent 侧边栏"，这就是 ScreenSide（看屏 GUI 自动化层）。共同主线：往期 Vol.041 讲"落地"，Vol.042 讲"供给"，Vol.043 讲"可信"，Vol.044 讲"经营"（收得到钱），这一期回到经营落地的三件基本功——算得清（运营毛利）、接得通（工具协议）、干得了（看屏杂活）。当生成、可信都不再稀缺，稀缺的是"让 agent 替你干活，还干得明白、算得清楚、接得顺畅"。
